阿里云服务器部署指南
====================

先说结论：
  **用 Git 方式部署时，不需要镜像仓库。** 服务器会自己现场构建镜像。
  但如果你想「构建一次、多台机器拉取」，或者想用 GitHub Actions 自动出镜像，
  那镜像仓库就派上用场了。两条路都写在下面，按需选。

  → 只想尽快跑起来：看【路线 A：Git 直接部署】（无需镜像仓库）
  → 想要现成镜像 / 多机分发 / 自动构建：看【路线 B：拉现成镜像（GHCR）】

  注：镜像仓库用 GitHub Container Registry (GHCR)，不用 Docker Hub。
      原因见第六节开头（Docker Hub 从国内访问不稳定）。


##############################################################
零、两条路怎么选
##############################################################

路线 A：Git 直接部署（推荐，最简单）
  docker compose up -d --build 里的 --build 就是「在当前目录现场构建」。
  你只要把几个文本文件传到服务器，服务器自己 build。
  适合：只有一台服务器、想改代码立刻生效。

路线 B：拉现成镜像（GHCR）
  用 GitHub Actions 先构建好镜像推到 GHCR，
  服务器只 docker pull，不构建。
  适合：
    - 有多个机器要部署（构建一次，处处拉取）
    - 服务器性能弱 / 磁盘小，不想在服务器上装构建环境
    - 想用 GitHub Actions 自动构建，push tag 就出镜像

  重要：路线 B 不要求你本机装 Docker。
  用 GitHub Actions 的话，构建在 GitHub 的服务器上完成，
  你本机只负责 git push。详见第六节。

要传的文件总共不到 100 KB，非常小：

    Dockerfile
    docker-compose.yml
    .dockerignore
    .env.example
    emby-proxy.js
    emby-missing-episodes.html
    deploy.sh
    .gitignore
    .github/workflows/docker-publish.yml
    README.md
    README.txt（可选）


##############################################################
一、路线 A：完整部署流程（Git 方式，无需镜像仓库）
##############################################################

【第 1 步】在你自己的电脑上，把项目推到 GitHub 仓库

  在项目目录执行：

      git init -b main
      git add .
      git commit -m "Emby 缺集检测工具"
      git remote add origin https://github.com/sadmion/emby-missing-episodes.git
      git push -u origin main

  如果仓库是在 GitHub 网页上先建好的，且初始化时勾了 README，
  本地已存在 README.md 会冲突，先执行 git pull --rebase origin main 再推。

  国内服务器拉取 GitHub 可能慢。如果你的服务器在国内，
  也可以改用 Gitee（把上面的地址换成 gitee.com 即可），速度更快：

      git remote add origin https://gitee.com/sadmion/emby-missing-episodes.git

  提示：如果 git 提示要你设置身份，先执行：

      git config --global user.name "sadmion"
      git config --global user.email "102721363+sadmion@users.noreply.github.com"

  提示：.gitignore 已经把 .env 排除掉了，Key 不会被提交，放心。


【第 2 步】SSH 登录你的阿里云服务器

      ssh root@你的服务器公网IP

  端口不是 22 的话： ssh -p 端口 root@IP


【第 3 步】安装 Docker（如果还没装）

  一条命令搞定，Ubuntu / CentOS / 阿里云 Linux 都适用：

      curl -fsSL https://get.docker.com | sh

  装完启动：

      systemctl enable --now docker

  验证：

      docker --version
      docker compose version

  如果 docker compose 提示找不到命令，试一下 docker-compose（中间是横线）
  能不能用。老版本 Docker 用横线形式。


【第 4 步】把代码拉到服务器

      mkdir -p /opt && cd /opt
      git clone https://github.com/sadmion/emby-missing-episodes.git
      cd emby-missing-episodes

  国内服务器拉 GitHub 慢的话，可以改用 SSH 方式（更快更稳）：
      git clone git@github.com:sadmion/emby-missing-episodes.git


【第 5 步】一键部署

      chmod +x deploy.sh
      ./deploy.sh

  脚本会自动：
    - 检查 Docker 是否装好、是否在运行
    - 从 .env.example 生成 .env
    - 构建并启动容器
    - 告诉你该怎么访问

  首次要下载 node 镜像，大概几分钟。


【第 6 步】访问

  默认配置下，服务监听 0.0.0.0（即对外可访问）。
  **前提**：到阿里云控制台 → 安全组，放行 8787 端口。

  然后浏览器直接打开：

      http://你的服务器公网IP:8787

  就能看到工具页面了。填 Emby 地址、Key，点开始检测。

  打不开？先按下面第二节末尾的「访问不了的三步排查」定位。

  ─────────────────────────────────────────────
  想更安全、完全不暴露到公网（可选）：
  编辑 .env 把 BIND_IP 改成 127.0.0.1，重新 up -d，
  然后在你自己的电脑上执行：

      ssh -L 8787:127.0.0.1:8787 root@你的服务器公网IP

  保持窗口别关，浏览器打开 http://127.0.0.1:8787 即可。
  详见第三节。


##############################################################
二、路线 B：拉现成镜像部署（经 GHCR）
##############################################################

适用场景：多台机器分发、服务器性能弱、或用 GitHub Actions 自动构建。

前提：镜像已经在 GitHub Container Registry (GHCR) 上。怎么把镜像推上去，
见下方第六节（用 GitHub Actions，你本机不需要装 Docker）。

【第 1 步】确认镜像地址

  本项目对应你的 GitHub 账号，完整镜像地址是：

      ghcr.io/sadmion/emby-missing-episodes:latest

【第 1.5 步】登录（GHCR 镜像默认私有，首次需要）

  echo "你的GitHubPAT" | docker login ghcr.io -u sadmion --password-stdin

  PAT：GitHub → Settings → Developer settings → Personal access tokens
       → 勾选 read:packages

  【更省事】把镜像设为公开，之后不登录也能拉：
      https://github.com/sadmion?tab=packages → 点进镜像
      → Package settings → Change visibility → Public

【第 2 步】服务器上直接运行（不用 clone 源码）

  一行搞定：

      docker run -d \
        --name emby-missing-episodes \
        --restart unless-stopped \
        -p 127.0.0.1:8787:8787 \
        --add-host=host.docker.internal:host-gateway \
        -e HOST=0.0.0.0 \
        -e PORT=8787 \
        -e TMDB_HOST=api.tmdb.org \
        ghcr.io/sadmion/emby-missing-episodes:latest

  参数说明：
    -p 127.0.0.1:8787:8787    只监听本机回环（安全），访问见第三节
    --add-host                 让容器能用 host.docker.internal 访问宿主机
    -e HOST=0.0.0.0            容器内必须监听 0.0.0.0，否则宿主机访问不到
    -e TMDB_HOST=api.tmdb.org  用国内可直连的 TMDB 域名

  想预填 Emby / TMDB 信息，再加：
    -e EMBY_URL=http://192.168.1.10:8096
    -e EMBY_KEY=你的Emby密钥
    -e TMDB_KEY=你的TMDB密钥

【第 3 步】用 compose 管理（推荐）

  **项目里已经带了一份现成的文件 `docker-compose.ghcr.yml`**，
  直接用它就行，不用自己写：

      docker compose -f docker-compose.ghcr.yml up -d
      docker compose -f docker-compose.ghcr.yml down      # 停止
      docker compose -f docker-compose.ghcr.yml logs -f   # 看日志
      docker compose -f docker-compose.ghcr.yml pull      # 更新镜像

  所以完整流程是（在服务器上）：

      git clone https://github.com/sadmion/emby-missing-episodes.git
      cd emby-missing-episodes
      cp .env.example .env        # 可选，想改端口/预填 Key 才需要
      docker compose -f docker-compose.ghcr.yml up -d

  两份 compose 文件的分工：

      docker-compose.yml         build: .            → 现场构建
      docker-compose.ghcr.yml    image: ghcr.io/...  → 拉现成镜像

  也可以完全不用 clone，手写一份最小的：

      services:
        emby-missing-episodes:
          image: ghcr.io/sadmion/emby-missing-episodes:latest
          container_name: emby-missing-episodes
          restart: unless-stopped
          ports:
            - "127.0.0.1:8787:8787"
          environment:
            HOST: "0.0.0.0"
            PORT: "8787"
            TMDB_HOST: "api.tmdb.org"
          extra_hosts:
            - "host.docker.internal:host-gateway"
          logging:
            driver: "json-file"
            options:
              max-size: "10m"
              max-file: "3"

【第 4 步】更新版本

  上游发了新版镜像后：

      docker compose -f docker-compose.ghcr.yml pull
      docker compose -f docker-compose.ghcr.yml up -d
      # 或不用 compose：
      docker pull ghcr.io/sadmion/emby-missing-episodes:latest
      docker stop emby-missing-episodes && docker rm emby-missing-episodes
      # 然后重新执行第 2 步的 docker run

  注意：换了镜像不会丢扫描结果——结果存在宿主机 ./data 目录里，
        容器只是挂载它，重建/换镜像都不影响。详见第五节。


##############################################################
三、关于访问方式的建议（安全，请一定看）
##############################################################

默认方式（BIND_IP=0.0.0.0，公网直连）：
  优点：浏览器直接打开 http://服务器IP:8787，方便。
  缺点：端口对公网开放。**本工具没有登录验证**，务必限制来源 IP。

  ⚠️ 如果部署完发现「服务明明是活的、但浏览器打不开」，
     99% 是下面两个原因之一，先查这两条：

     1) 端口只绑在了 127.0.0.1（历史默认值，或你手动设过）
        诊断： docker compose -f docker-compose.ghcr.yml port emby-missing-episodes 8787
        输出 127.0.0.1:8787 → 就是这个原因。公网绝对连不上，改成 0.0.0.0 即可。
        输出 0.0.0.0:8787   → 绑定正常，往下查第 2 条。

     2) 阿里云安全组没放行 8787
        阿里云控制台 → 实例 → 安全组 → 入方向 → 添加规则
        协议 TCP，端口 8787，授权对象填你自己的公网 IP（别用 0.0.0.0/0）

  改完 BIND_IP 后重启：

         docker compose -f docker-compose.ghcr.yml up -d

      （compose 会检测到端口配置变化，自动重建容器，不用先 down）

  顺带确认服务本身是活的：

         curl -I http://127.0.0.1:8787/__health
         # 返回 200 说明容器内部一切正常，问题必然在「对外暴露」层

更安全的替代方式（SSH 隧道）：
  优点：8787 端口完全不对外开放，别人扫不到。
  缺点：每次访问要开个 SSH 窗口。

  1. 编辑服务器上的 .env：

         nano .env        # 把 BIND_IP 改成 127.0.0.1，Ctrl+O 保存，Ctrl+X 退出

  2. 重新部署：

         docker compose -f docker-compose.ghcr.yml up -d

  3. 在你自己的电脑上执行：

         ssh -L 8787:127.0.0.1:8787 root@你的服务器公网IP

     保持窗口别关，浏览器打开 http://127.0.0.1:8787

重要：这个工具本身没有登录验证。一旦对公网开放，
      任何人都能访问。所以务必限制安全组来源 IP，
      或者干脆用 SSH 隧道方式。


##############################################################
四、Emby 地址怎么填（最容易踩的坑）
##############################################################

**容器里的 localhost 指的是容器自己，不是你的电脑。**

按你的实际情况填：

  情况 A：Emby 就在这台阿里云服务器上
          填  http://host.docker.internal:8096

  情况 B：Emby 在你家里的电脑 / 群晖 / NAS 上（最常见）
          填  http://192.168.1.10:8096   （改成实际内网 IP）

  情况 C：Emby 在另一台有公网 IP 的服务器上
          填  http://那台服务器的IP:8096

特别注意情况 B：
  如果 Emby 在你家里的局域网里，而阿里云服务器在公网，
  两者**默认是互相访问不到的**。你需要：
    - 让 Emby 有公网访问能力（端口映射 / 内网穿透 / frp 等），或
    - 在能访问到 Emby 的机器上部署这个工具（比如家里的 NAS / 软路由）

  如果你只是想在这台阿里云服务器上跑、但 Emby 在家里，
  这个架构本身就不通，需要先解决网络连通性。


##############################################################
五、扫描结果存在哪 / 会不会丢
##############################################################

经代理打开页面时（http://服务器IP:8787 或 SSH 隧道），扫描结果会自动存到
服务器目录：

      ./data/emby-missing-result.json

这个目录在 docker-compose.yml 里挂载到了宿主机，也就是：

      宿主机 /你的项目目录/data/emby-missing-result.json

带来的好处：
  - 下次打开页面**自动加载**这份结果，不用手动导入
  - 换个浏览器、换台电脑访问同一个地址，都能看到同一份结果
  - docker compose down / 重建容器 / 换镜像，结果都还在（存在宿主机上）

相关命令：

      ls -lh data/                       看结果文件大小和时间
      cat data/emby-missing-result.json  查看内容（JSON）
      rm data/emby-missing-result.json   手动清空（下次扫描重新生成）

页面里点「重新扫描」会同时删掉服务器上这份结果。

注意：如果不挂载这个目录（非 compose 方式手跑 docker run），容器一删结果
就没了。所以用 docker run 的话记得加 -v：

      docker run -d --name emby-missing-episodes \
        -p 127.0.0.1:8787:8787 \
        -e HOST=0.0.0.0 \
        -e DATA_DIR=/app/data \
        -v "$PWD/data:/app/data" \
        emby-missing-episodes:latest

另外，结果也会存进浏览器 localStorage；直接双击 HTML（file:// 方式）没有
服务器，只能用「导出/导入文件」方式保存。


##############################################################
六、把镜像推到镜像仓库（用 GitHub Actions，本机无需 Docker）
##############################################################

如果你本机没装 Docker，又想有个现成镜像可用，就用 GitHub Actions：
GitHub 的服务器上有 Docker，它替你 build 并 push 到镜像仓库。

【用哪个仓库？GHCR，不要用 Docker Hub】

  本项目已配置为推送到 **GitHub Container Registry (GHCR)**，原因：

    1. 零配置 —— 用 GitHub 内置的 GITHUB_TOKEN 认证，不用注册账号、不用配 Secret
    2. 稳定 —— 走 GitHub 自己的网络，不受国内访问 Docker Hub 的网络问题影响
    3. 免费 —— 公开镜像无限量
    4. 拉取同样简单

  （Docker Hub 从国内 runner 访问常失败，报 malformed / timeout 之类；
    换 Token 也没用，因为问题在网络链路而非凭据。）

【第 1 步】触发构建（无需任何配置）

  仓库里已经有 .github/workflows/docker-publish.yml，推一个 tag 就会自动跑：

      git tag v1.0.0
      git push origin v1.0.0

  也可以在 GitHub 仓库 Actions 页面找到 "Build and Push Docker Image"，
  点 "Run workflow" 手动触发。

【第 2 步】查看结果

  Actions 页面能看到构建日志和进度（绿勾=成功）。
  成功后镜像地址：

      ghcr.io/sadmion/emby-missing-episodes:1.0.0
      ghcr.io/sadmion/emby-missing-episodes:latest

  同时提供 linux/amd64 和 linux/arm64 两种架构，
  群晖 / 树莓派等 ARM 设备也能直接用。

【第 3 步】在服务器上拉取使用

  GHCR 的镜像默认是私有的，首次拉取要先登录一次：

      echo "你的GitHubPAT" | docker login ghcr.io -u sadmion --password-stdin
      docker pull ghcr.io/sadmion/emby-missing-episodes:latest

  PAT 申请：GitHub → Settings → Developer settings → Personal access tokens
            → 勾选 read:packages 权限

  【推荐】把镜像设为公开，之后任何人（包括你的服务器）不登录也能拉：

      1. 打开 https://github.com/sadmion?tab=packages
      2. 点进 emby-missing-episodes
      3. 右侧 Package settings → Danger Zone → Change visibility → Public

【第 4 步】用 compose 部署（可选）

      services:
        emby-missing-episodes:
          image: ghcr.io/sadmion/emby-missing-episodes:latest
          container_name: emby-missing-episodes
          restart: unless-stopped
          ports:
            - "127.0.0.1:8787:8787"
          environment:
            HOST: "0.0.0.0"
            PORT: "8787"
            TMDB_HOST: "api.tmdb.org"
          extra_hosts:
            - "host.docker.internal:host-gateway"

  （更完整的 compose 示例见项目根目录的 README.md）

注意事项：
  - 免费版 GitHub Actions 有分钟数限制，公开仓库不受限。
  - 每推一个 tag 就会构建一次，版本号即 tag 名。
  - 重新构建会覆盖相同 tag 的镜像。


##############################################################
七、日常维护命令
##############################################################

⚠️ 用哪个 compose 文件，命令里就要一直带着对应的 -f。
   下面以 docker-compose.ghcr.yml（拉镜像方式）为例。
   若你用的是源码构建方式，把 -f 参数换成 -f docker-compose.yml，并去掉 -f 那串。

在项目目录下执行：

  docker compose -f docker-compose.ghcr.yml logs -f      实时看日志
  docker compose -f docker-compose.ghcr.yml ps           看运行状态
  docker compose -f docker-compose.ghcr.yml restart      重启
  docker compose -f docker-compose.ghcr.yml down         停止并删除容器
  docker compose -f docker-compose.ghcr.yml up -d        再次启动

查看容器资源占用：

  docker stats emby-missing-episodes

--------------------------------------------------------------
更新到新版本
--------------------------------------------------------------

最省事的方式：

  ./update.sh

（自动拉镜像 + 重建 + 健康检查，失败会提示回滚命令）

手动方式：

  docker compose -f docker-compose.ghcr.yml pull
  docker compose -f docker-compose.ghcr.yml up -d

如果你是源码构建方式（docker-compose.yml）：

  git pull
  docker compose up -d --build

更新后想清理旧镜像释放磁盘：

  docker image prune -f

**更新不生效？** 检查 .env 里的 IMAGE_TAG：

  grep IMAGE_TAG .env

  若是 1.0.0 这类具体版本号 → 被锁定了，改成 latest 再 up -d。

**想回滚到旧版本**：

  IMAGE_TAG=1.0.0 docker compose -f docker-compose.ghcr.yml up -d

完整说明见同目录的「更新指南.txt」。


##############################################################
八、常见问题
##############################################################

Q: deploy.sh 提示 "Permission denied"
A: 先执行 chmod +x deploy.sh

Q: deploy.sh 报错 "bash: $'\r': command not found"
A: 说明文件被转成了 Windows 换行符。在服务器上执行：
       sed -i 's/\r$//' deploy.sh
   然后重新运行。（正常情况不会出现，文件本身是 LF 换行）

Q: docker compose 提示 command not found
A: 老版本用 docker-compose。或者参考阿里云文档升级 Docker。

Q: 拉代码很慢 / 失败
A: 国内服务器拉 GitHub 可能慢，建议用 Gitee。
   或者配代理： git config --global http.proxy http://代理地址:端口

Q: 构建时下载 node 镜像很慢
A: 配阿里云镜像加速器：
       阿里云控制台 → 容器镜像服务 → 镜像加速器 → 按说明配置
   配置后执行： systemctl restart docker

Q: 浏览器打不开 / 显示「无法访问此网站」（**最高频问题**）
A: 按顺序查这三步，基本 1、2 步就能定位：

   1. 容器是否在跑
         docker compose -f docker-compose.ghcr.yml ps
      Status 应显示 Up (healthy)。

   2. 端口绑在哪（90% 的死结都在这）
         docker compose -f docker-compose.ghcr.yml port emby-missing-episodes 8787
      输出 127.0.0.1:8787 → 只绑了回环，公网必然连不上。
                            改 .env 里 BIND_IP=0.0.0.0 后重新 up -d。
      输出 0.0.0.0:8787   → 绑定正常，去查第 3 步。

   3. 阿里云安全组是否放行 8787
      控制台 → 实例 → 安全组 → 入方向 → 加规则（TCP 8787，来源限自己 IP）

   服务本身是否正常（辅助确认）：
         curl -I http://127.0.0.1:8787/__health
   返回 200 → 服务没问题，卡在「对外暴露」层（绑定地址 / 安全组 / 系统防火墙）
   连不上 → 服务自身有问题，看 docker compose -f ... logs -f

Q: 检测时提示连不上 Emby
A: 见第四节。多半是地址写了 localhost，或者网络本身不通。

Q: 扫描结果存在哪？重启服务器会丢吗？
A: 存在你**浏览器**的 localStorage 里，不在服务器、不在容器。
   所以重启服务器、重建容器都不影响结果。
   但换了浏览器、用了无痕模式、清了浏览器数据就会丢。

Q: 端口 8787 被占用了
A: 改 .env 里的 PORT，比如改成 8899，然后重新部署。
   注意 SSH 隧道命令里的端口也要跟着改。

编辑服务器上的 .env：

    nano .env

把这几行填上：

    EMBY_URL=http://192.168.1.10:8096
    EMBY_KEY=你的Emby密钥
    TMDB_KEY=你的TMDB密钥

保存后重新部署：

    docker compose up -d --build

之后打开网页，这三项会自动填好，直接点「开始检测」就行。

更新指南（给使用者）
==============================================================

本文档面向「部署了这个工具的人」，讲清楚怎么把旧版本升到新版本。

如果你是自己维护这个项目的开发者，看第六节「维护者：怎么发布新版本」。


##############################################################
一、更新有多简单（一句话版）
##############################################################

    cd 项目目录
    ./update.sh

就完了。脚本会自动拉新镜像、重建容器、做健康检查，失败还会提示怎么回滚。

没有这个脚本的话，等价的手动两条命令：

    docker compose -f docker-compose.ghcr.yml pull
    docker compose -f docker-compose.ghcr.yml up -d


##############################################################
二、更新前必看：两件事不会丢
##############################################################

1. **扫描结果不会丢**
   结果存在你**浏览器**的 localStorage 里，服务器和容器里根本没有。
   所以重建容器、重启服务器都不影响。

   ⚠️ 但换浏览器、用无痕模式、清浏览器数据会丢。重要的结果记得导出。

2. **配置不会丢**
   Emby 地址、Key、端口等都在 `.env` 文件里，更新不动这个文件。


##############################################################
三、标准更新流程（拉镜像方式）
##############################################################

【第 1 步】进项目目录，看当前版本

    cd emby-missing-episodes
    docker compose -f docker-compose.ghcr.yml images

  输出里的版本号记一下，万一新版有问题可以回滚回来。


【第 2 步】执行更新

    方式 A（推荐，带健康检查）：
        ./update.sh

    方式 B（手动，两条命令）：
        docker compose -f docker-compose.ghcr.yml pull
        docker compose -f docker-compose.ghcr.yml up -d


【第 3 步】验证

    浏览器打开 http://你的服务器IP:8787 ，看页面是否正常。

    或者命令行确认：
        curl -I http://127.0.0.1:8787/__health
        # 返回 200 就是好的


【第 4 步】清理旧镜像（可选，释放磁盘）

    docker image prune -f


##############################################################
四、⚠️ 更新不生效？99% 是这两个原因
##############################################################

**原因 1：用了 latest 标签，但本地缓存没失效**

症状：明明更新了，功能还是老样子。

原理：docker 看到本地已有 `xxx:latest`，就认为不用再去远程拉。

解决：compose 文件里已经配了 `pull_policy: always`，正常不会遇到。
     如果手动 docker run 起的容器，加 `--pull always`：

         docker run -d --pull always ... ghcr.io/sadmion/emby-missing-episodes:latest

     判断当前容器到底跑的是哪个版本：

         docker inspect --format='{{.Image}}' emby-missing-episodes
         # 对比新镜像 ID，一致就说明确实更新了


**原因 2：改过 .env 里的 IMAGE_TAG，锁死在旧版本上了**

症状：更新命令都执行成功了，但版本号不变。

检查：

         grep IMAGE_TAG .env

     如果显示 `IMAGE_TAG=1.0.0` 这种具体版本号，那就永远拉这个版本 —— 这是
     「锁定版本」的用法，不是 bug。想跟着最新走：

         echo "IMAGE_TAG=latest" >> .env      # 或直接删掉这行
         docker compose -f docker-compose.ghcr.yml up -d


##############################################################
五、出问题怎么回滚
##############################################################

新版有 bug、页面打不开，退回上一个版本：

【方式 A】回到指定版本号（推荐，最可靠）

    编辑 .env，指定要用的版本：

        IMAGE_TAG=1.0.0

    然后重建：

        docker compose -f docker-compose.ghcr.yml up -d

    看有哪些版本可选：
        https://github.com/sadmion/emby-missing-episodes/pkgs/container/emby-missing-episodes


【方式 B】update.sh 会告诉你精确的回滚命令

    脚本在更新前会打印类似：
        回滚命令: IMAGE_TAG=1.0.0 docker compose -f docker-compose.ghcr.yml up -d

    直接复制执行即可。


【回滚后想再升级】把 .env 里 IMAGE_TAG 改回 latest，重新 up -d。


##############################################################
六、维护者：怎么发布新版本
##############################################################

改了代码之后，让别人能拿到更新：

【第 1 步】推代码到 main

    git add .
    git commit -m "修复 xxx"
    git push

  → **这一步就会自动构建镜像并更新 latest 标签**（约 1-2 分钟）。
    别人执行 ./update.sh 就能拿到这次改动。不用做别的。

  → 到 Actions 页面可以看构建进度：
    https://github.com/sadmion/emby-missing-episodes/actions


【第 2 步】想发正式版本号时，打个 tag

    git tag v1.0.1
    git push origin v1.0.1

  → 会额外产出 1.0.1 / 1.0 / 1 三个标签，方便别人锁定版本。
  → latest 也会跟着指向这个新版本。

  什么时候该打 tag：
    - 攒了一批改动，想给别人一个"稳定版"
    - 改动有破坏性，需要让别人知道"这是个新版本，注意"
    - 平时小修小补，直接 push main 就行，不必打


【改镜像的触发条件】编辑 .github/workflows/docker-publish.yml：

    on:
      push:
        branches: [main]      # 删掉这行 → 只有打 tag 才构建
        tags: ["v*.*.*", "v*.*"]
      workflow_dispatch:       # 保留 → 网页上还能手动点按钮触发


【手动触发构建】不想推代码，只想重新构建一次：

    Actions 页面 → 左侧选 "Build and Push Docker Image"
    → 右上 "Run workflow" → 选分支 → Run


##############################################################
七、常见问题
##############################################################

Q: 更新要多久？
A: 拉镜像通常十几秒到 1 分钟（取决于网络）。update.sh 从开始到验证完成
   一般 1 分钟内。

Q: 更新时服务会中断吗？
A: 会短暂中断几秒（容器重建）。这是单机部署的正常现象。
   本工具是个人使用场景，几秒中断无影响。

Q: 能自动更新吗？
A: 可以用 `watchtower` 之类的工具，但对本工具没必要 —— 它没有安全更新需求，
   手动更新更能控制节奏。想配的话告诉维护者。

Q: 更新后 Emby 地址/Key 要重填吗？
A: 不用。在 .env 里配的不会丢；在网页里手填的存在浏览器里，也不会丢。

Q: 拉镜像很慢 / 超时？
A: 国内服务器访问 ghcr.io 偶尔慢。重试一次通常就好。持续不行可以：
   1. 配 Docker 代理
   2. 改用源码构建方式（见下）

Q: 我是用 git clone 源码构建的（docker-compose.yml），怎么更新？
A: 命令不同：

       git pull
       docker compose up -d --build

   注意是 `docker-compose.yml`（带 build: . 的那份），
   不要带 -f docker-compose.ghcr.yml。

Q: 两个 compose 文件到底用哪个？
A:
   | 文件 | 更新命令 | 说明 |
   |---|---|---|
   | docker-compose.ghcr.yml | pull + up -d | 拉现成镜像，快（推荐） |
   | docker-compose.yml | git pull + up -d --build | 现场构建，慢但可改代码 |
